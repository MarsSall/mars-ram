# Threat model

**Status:** Living document · Update it when an asset, attacker, or entry point changes (skill `product-security`).

## Assets

| Asset | Where it lives | Protection |
|-------|----------------|------------|
| The app's SSH private key | Android Keystore on the phone | Non-exportable; device unlock required by default (PRD R1); the user may turn it off, which rotates to a new key on every computer |
| Access to the user's computer | Host `authorized_keys` entry for the app key | Added by QR pairing after an explicit yes at the computer, or by hand; restricted to `restrict,port-forwarding,pty`; on Windows administrators it grants administrator access |
| Pairing code | QR and link on the computer's screen, valid 5 minutes | One use, constant-time check, 5 invalid requests close it, the user must still confirm at the computer |
| Bridge token | Host registry file `~/.<appId>/bridges/<id>.json` | Readable only by the host user (0600 / single-SID ACL); constant-time comparison; never logged |
| Live session content | Pi process on the host; streamed to the phone | Bridge listens on host `127.0.0.1` only; reached through the SSH tunnel |
| Pinned host identities | App storage (planned) | A changed identity is refused, never accepted silently |

## Attackers and entry points

| Attacker | Entry point | Mitigation | Status |
|----------|-------------|------------|--------|
| Someone holding the unlocked phone | Opening sessions on the computer | Device unlock to use the key, 300 s validity; if the user turns it off (after a warning), nothing stops this | Implemented |
| A process on the computer or a malformed authorized_keys | Key rotation (`mars-ram key add|remove`) | Only lines sshd would accept for plain-key login (a short option allow-list, no duplicates) can vouch for `--like`/`--keep`; the old key is removed only while the new one is trusted and after the phone proved it with a fresh connection; backup, atomic rewrite keeping owner/ACL | Implemented; native Windows ACL checked end to end only |
| Someone holding the unlocked phone | Herdr switcher (`mars-ram herdr list|focus`) over authenticated SSH exec | May list every workspace/tab (including non-Pi), bounded labels, agent kinds/statuses and active-tab git branch, and change shared workspace/tab focus (the PC follows). Cannot create/close targets, send input, read session files, or select a command/cwd. Fixed verbs; strict scoped ids and existence checks before focus; recorded validated Herdr executable or platform PATH fallback; shell-free argv, per-child 3 s Herdr / 2 s git deadlines (SIGTERM, then SIGKILL after 250 ms grace; independent timeout rejection without waiting for exit), 1 MiB buffers/output, four concurrent workspace lookups. These are per-process, not whole-list deadlines. Killing stops the direct child on Linux and Windows, not its descendants. Git uses only the active tab's first pane cwd; failure returns null. | Implemented; native Windows and phone verification pending |
| Malformed or hostile Herdr metadata | Herdr CLI JSON consumed by the switcher | Drop malformed/duplicate rows and cross-workspace tabs; bound counts (128 workspaces, 128 tabs each), report count overflow with `truncated: true` and a muted drawer warning, labels (256 characters, including first-pane title fallback for numeric tab labels) and final output (1 MiB); sanitize controls; no raw pane/cwd/session paths or child-process errors in the response. Git runs with shell-free fixed argv; no session file is opened. Invalid ids return BAD_ID before any process; missing targets never trigger focus. | Implemented; fake-runner rejection tests |
| Someone holding the unlocked phone, or a hostile repository the user opened | Project browser (`mars-ram project tree|file|status|diff|log|show|branches|stage-link`) over authenticated SSH exec | May read, as the same SSH user, the files and Git history of the project open in a Herdr workspace: the git top-level of the workspace's active-tab first-pane cwd (or that cwd outside Git; a cwd inside `.git` browses the work tree around it). The phone names only a workspace id (`w…`, or the focused one), never a root path; paths travel as `--path-b64` so no remote shell reinterprets them. Paths are relative POSIX segments: no empty, `.`/`..`, `:`, control character, backslash, drive, or `.git` alias (case, trailing dots/spaces, `GIT~n`). The realpath must stay inside the root and outside `.git`; reads open with `O_NOFOLLOW`, recheck a regular file on the handle, and after reading re-resolve the path and require the same device/inode inside the root (an unknown identity, inode 0, fails closed), so a parent folder swapped for a link between check and open is refused (untracked diffs are built from that checked read, never `git --no-index`). Git runs shell-free with fixed argv, `--literal-pathspecs`, `--no-optional-locks`, `core.fsmonitor=false` and `--attr-source` at the empty tree (no tracked `.gitattributes` applies), every configured filter (also reachable through `.git/info/attributes` or `core.attributesFile`) overridden per call with identity `cat` and no process (a name that cannot be overridden fails closed), plus `--no-ext-diff --no-textconv`; no writing command (checkout, stage, commit, fetch). `show`/`diff --commit` accept only commit objects; `log` reports failures except an unborn branch. Bounds: 500 entries/changes/branches with `truncated` (current branch first), at most 2000 names stat'ed per folder, 256 KiB text and diff (a bigger diff is cut, not failed), 2 MiB images, 4 MiB output, 3 s per git/Herdr child (direct child only, not descendants), 5 s for the read; then up to 5 s for the SSH pipe to accept the line, as with `servers`. `stage-link` copies one checked regular file (≤ 25 MiB) into the link server's staging dir only if that dir is a real directory with no linked parent (`O_EXCL|O_NOFOLLOW`, 0600), under a name the link server accepts; a copy whose write finishes after the deadline is removed; the link itself is created by the link server. Residual: programs named by the repository's own `.git/config` beyond those disabled (e.g. a custom merge or credential helper) are not invoked by these reads; Windows aliases are rejected lexically and by the realpath check but not verified on a native host yet. | Implemented; independent verify (07e277a: fail) fixed with RED→GREEN tests on real temporary repos (hostile fsmonitor, clean filter, external diff, textconv; parent swap races; `.git` cwd; staging link; non-commit ids; unborn vs broken log; 500+ branches; huge diffs); Linux real run; Windows and phone pending |
| Someone holding the unlocked phone, or a hostile repository | Guided shortcuts (`mars-ram repos` / `launch`) over paired SSH | Lists canonical Git repos under host-configured roots (default Work), depth ≤ 3, 500 results, no descent into repos, hidden folders, node_modules or directory links. Launch accepts only a fresh scan result and the installed-program allowlist gentle-shell / pi / opencode; rejects traversal, symlink aliases/escapes and non-repos. Reuses matching live Herdr cwd/program metadata or creates and focuses a labelled workspace. Cannot accept arbitrary commands, program arguments, arbitrary cwd or close workspaces. Herdr subprocesses use shell-free arrays, scoped IDs, 5 s child deadlines and 1 MiB responses; pane run receives only a hard-coded allowlisted literal, never caller text. Root edits require local interactive TTYs without SSH markers; this is an accident-prevention guard, not authentication against the already-authorized same-user SSH account. Residual: Herdr submits the literal to its shell; PATH/aliases and repository code remain trusted (Windows shell lookup may search cwd). Agents retain the user's privileges. Filesystem TOCTOU, duplicate concurrent launches, delayed detection and partial-created workspaces remain possible; no runtime sandbox or whole-operation deadline. See [host CLI contract](host-cli.md). | Implemented; fake-port tests; native Windows and phone checks pending |
| Someone holding the unlocked phone | Servers list (`mars-ram servers list`) over authenticated SSH exec, and the viewer tunnel | May list the SSH user's own TCP listeners (port, bind address, process name, pid, folder on Linux) and open a loopback tunnel to any port of the computer, as SSH port forwarding already allowed (`restrict,port-forwarding,pty`). Cannot see other users' processes, choose a command or arguments, or reach other machines: the native forward accepts only remote host 127.0.0.1 or ::1. Fixed verb; Linux reads `/proc` with no external binaries; Windows runs a fixed shell-free PowerShell script with no interpolated input and passed with `-EncodedCommand`, snapshots listeners once and keeps a listener only when its process started before that snapshot and its token's user SID (fixed P/Invoke `OpenProcessToken`) is the current user's; a live pid that predates the snapshot is the process that held the listener, so a pid reused by another account is dropped; ≤ 64 entries with `truncated`; HTTP probe 750 ms per port, 8 at a time, HTTP status line checked whole; discovery and probes ≤ 4 s, then up to 5 s for the SSH pipe to accept the line (exit 1 if it never drains, never cut JSON). | Implemented; independent verify (Linux, adversarial listeners); Windows real run passed (6 own listeners, 1.3 s) |
| Hostile page served by a computer's server | In-app WebView over the tunnel | Incognito (no cookies shared between tunnels or computers), no JS bridge or injected script, no file or content access, no mixed content, no automatic windows; navigation limited to `http://127.0.0.1:<tunnel port>/`, other https links open in the browser and anything else is blocked. Cleartext allowed only to 127.0.0.1, localhost and `*.ts.net` names (added for pairing). A page in the viewer can therefore also load cleartext subresources from `*.ts.net` names; they travel inside Tailscale, and only the navigation is restricted, not subresources. While the viewer is open, other apps on the phone can reach the tunnel's random loopback port, as with the bridge tunnel. | Implemented; phone check pending |
| A nearby person, an app on the phone, or a tampered model download | Voice dictation (on-device Parakeet through whisper.rn) | `RECORD_AUDIO` is requested only when a mic is pressed. The microphone is open while a mic is held or locked, and briefly after a first short tap while a possible second tap is awaited (a 300 ms window checked by a 100 ms JS timer, so about 0.3–0.4 s, longer if the JS thread is busy). Each mic runs its own `DictationRunner`: a cancel, leaving the foreground or leaving the screen bumps an epoch at once (never queued behind a start-up), so a queued start never runs and a start-up in progress is told to stop before the recorder opens; late results are not delivered. The adapter gives the recorder to one mic at a time (another gets busy and cannot stop, cancel or finish it) and keeps it until the owner's audio is collected. A 2 min cap applies while the app runs (a JS timer, not a native deadline). Audio stays in memory, is transcribed on the phone and dropped, never written to disk or sent anywhere. A transcription past 30 s is aborted (the native stop is a request; the engine waits up to 3 s for it to settle) and its result discarded. The text goes to the chat draft (sent only by the user) or is typed at the terminal prompt as one bracketed paste with line breaks and control bytes removed, so dictation can never press Enter. The model (Parakeet TDT 0.6B v3 q4_0, 355 615 679 bytes) comes from an immutable Hugging Face revision; a download is accepted only with the pinned size and MD5 (its SHA-256 matches the published LFS id), an installed file is checked by MD5 once per app run and by size right before loading, and a mismatching file is refused (an interrupted `.part` is deleted at start or when the sheet closes). Transcription never reaches the network; Cyrillic output is spelled with Latin letters. The debug build additionally declares `ACCESS_LOCAL_NETWORK` (React Native dev server); release builds do not. | Implemented; gesture, runner and adapter lifecycle unit-tested with fake engines and mocked native modules; phone-checked (terminal, double tap, floating chat); independent verify rounds 1–2 FAIL fixed |
| Someone on the tailnet or LAN | Bridge port on the host | Loopback-only listener, per-instance token | Implemented |
| Other users on the host | Registry file with the token | User-only permissions | Implemented, verified on Linux and Windows |
| A machine impersonating the host | SSH connection | Host identity pinning by fingerprint; with QR pairing the identity comes from the QR, by hand the user compares it on the computer | Implemented |
| Someone who photographs the pairing QR | Pairing endpoint on the tailnet | Needs to be on the user's tailnet, within 5 minutes, before the real phone, and the user must answer yes at the computer to a request showing the phone's name and key fingerprint | Implemented |
| Any app or web page on the phone | External system links (store and preview schemes) | `+native-intent.tsx` applies the pure `core/link-policy.ts` allowlist on cold start and warm links: external links can only open Inicio (`/`) or the pairing confirmation (`/pair?p=…`). Only the exact `pair` route with exactly one non-empty literal `p` parameter and nothing else is allowed, and its raw value is preserved; a link with any other parameter, a triple slash or an encoded parameter name goes to Inicio. All other routes, schemes and malformed inputs go to Inicio without their parameters; internal navigation is unchanged. External links cannot reach the terminal, computer/session discovery, repository listing or key initialization routes. Opening a pairing link only decodes it on the phone, with no network request; the app shows «¿Agregar esta computadora?» with the computer's name and address (MagicDNS name, else the tailnet address) from the link, and sends this phone's public key only after the user taps «Agregar». An invalid or expired link shows the pairing error and a way to scan instead; a disallowed system link opens Inicio. After «Agregar» the link pairs exactly like a scanned QR, so the computer still asks its user before accepting the key. Residual: the name is whatever the link's author wrote; the address is what to check. A link made by someone else could save a computer that is not the user's if that computer's user accepts the key (only the public key is sent; the phone then trusts that computer's identity from the link). | Implemented; one-line-install L27 MEDIUM external-link PTY/Herdr-focus finding fixed by the system-link allowlist; core, cold/warm hook and text tests; allowlist phone check pending |
| A network between the phone and the computer | The pairing request (code and the phone's public key) | Plain HTTP sent only to the computer's MagicDNS name from the QR (lowercased, one trailing dot removed, accepted only as a host under `ts.net`), never to the IP address. MagicDNS names resolve to tailnet addresses, so the request travels inside Tailscale's WireGuard encryption. Without a usable name the phone stops before any request and asks to turn on MagicDNS. Android's network security config allows cleartext only to `*.ts.net` and loopback; the base config stays cleartext-off. The config allows every `*.ts.net` name app-wide: pairing sends cleartext there, and so can a page shown in the servers viewer (subresources; see the WebView row). Residual: the app checks the name's suffix, not the address it resolves to or the route; if the phone resolved it outside Tailscale (for example without Tailscale's DNS), the request could leave the tailnet in clear. Public Funnel names serve HTTPS only, so they do not offer a working cleartext pairing endpoint. The request carries only the one-time code and a public key, and the user still confirms at the computer. | Implemented; fake-port and config tests; phone check pending |
| A request crafted to inject `authorized_keys` options | Pairing request | Only one-line ECDSA/Ed25519 keys without options are accepted; the device name cannot hold control characters | Implemented |
| Other apps on the phone | Tunnel port on the phone's 127.0.0.1 | Tunnel reaches only the bridge port; the bridge still requires its token | Implemented; any phone app can reach the local port |
| A compromised dependency | npm and Maven packages | Exact pins, lockfile, 3-day release age, trust-downgrade check, blocked install scripts, `pnpm audit` | In place; 3 dev-tool advisories without published fixes |
| Someone holding the unlocked phone | The terminal on the computer | The native module runs only Herdr, through an exec request with a PTY, never the default shell; output and input are never logged. This is not a sandbox: Herdr itself opens shells on the computer, which is what the user authorized the key for | Implemented, by design |
| Someone on the tailnet | Link server port on the host | Listens only on the Tailscale address while links are valid; only `/l/<token>` with 256-bit tokens compared in constant time; images inline, everything else downloads with `nosniff` and a sandbox CSP; 4 downloads at a time with deadlines; a deleted or expired link stops serving, including ongoing downloads | Implemented; anyone on the tailnet holding a link can open it for a day (accepted) |
| Other users on the host | Link copies and the link server's commands | `~/.mars-ram/links` private (0700/0600, user-only ACL on Windows); tokens never on a command line or in logs; `stop` only ends a server whose boot identity it confirms | Implemented; Windows ACL not yet checked live |
| Content sent to the agent | Uploaded files or images with hidden instructions | The app shows every attachment, with image previews, before sending, and the user can remove it | Implemented, checked on the phone |
| A crafted attachment name | Files outside the uploads folder | Names only (no paths) checked by the protocol schema; the bridge refuses links, hard links, a linked folder, and unfinished uploads, and reads through the handle it checked | Implemented, verified on Linux and Windows |
| Other users on the host | Uploaded attachments | Uploads folder created `0700` with files `0600` on Linux; on Windows it inherits the user-only `~/.mars-ram`; removed after the chosen retention | Implemented, checked on Linux and Windows |

## Known gaps

- The Herdr-only allow-list limits what the phone asks to run, not what the computer allows: a server-side `ForceCommand` can replace the program, and Herdr gives shells. The key's `restrict,port-forwarding,pty` options are the real boundary.
- The Bouncy Castle provider swap is process-wide (`apps/mobile/modules/ssh/README.md`).
- Closing a tunnel's SSH channel can block while the module's lifecycle lock is held, so a slow host can delay other connects and disconnects.

Shortcut program lookup: `host.json` › `programs` holds absolute paths written only by a local `mars-ram install`; `launch` uses them solely to check that an allowlisted program exists and never executes them directly (the Herdr pane runs the fixed program name). Anyone who can write `host.json` could only change that presence check, not which program runs.
